# TCR DB 엔진 개발 스케줄

2026년 8월부터 12월까지 TCR DB 엔진 개발 전체 트랙을 **마인드맵**과 **주간 스케줄 테이블**로 관리하는 도구입니다.

주간 업무 보고용이 아닙니다. 한 주 단위 칸이 8–12월 22주에 걸쳐 이어지므로, 스토리지·쿼리·트랜잭션·복제·품질 경로가 언제 겹치는지 한 화면에서 볼 수 있습니다.

## 구성

- **마인드맵**: 아키텍처, 스토리지 엔진, 쿼리 엔진, 트랜잭션, 복제·HA, 운영, 품질·릴리스 작업 분해. 노드를 클릭하면 아래 테이블이 해당 하위 업무만 보여 줍니다.
- **주간 테이블**: 2026-08-03(월)부터 2026-12-28(월)까지 월요일 시작 22주. 칸 클릭으로 `예정 → 진행 → 완료 → 지연`을 바꿉니다.
- **이번 주 보드**: 오늘이 속한 주에 칸이 있는 업무만 모아 봅니다.
- **상세 패널**: 담당, 메모, 주간 상태, 구간 일괄 완료/예정.
- **스케줄 저장함**: 이름을 붙여 여러 안을 저장하고 다시 불러옵니다.

기준 계획의 현재 시점(2026년 8월 말)은 설계 스파이크가 끝나고 페이지 매니저·프로토콜 스펙이 진행 중인 상태로 채워 두었습니다. 「기본 계획으로」로 언제든 되돌릴 수 있습니다.

## 저장하고 다시 불러오기

화면 맨 위 저장함 줄에서 처리합니다.

| 버튼 | 동작 |
| --- | --- |
| 다른 이름으로 저장 | 지금 상태를 새 이름으로 저장합니다. 같은 이름이 있으면 `이름 (2)`로 자동 구분합니다. |
| 저장 | 현재 불러와 있는 이름에 덮어씁니다. 이름이 없으면 「다른 이름으로 저장」으로 안내합니다. |
| 불러오기 (n) | 저장 목록을 펼칩니다. 항목별로 불러오기, 이름 변경, 삭제, 내보내기를 할 수 있습니다. |
| 파일로 내보내기 / 파일 가져오기 | JSON 파일로 주고받습니다. 다른 PC나 브라우저로 옮길 때 씁니다. |

- 편집하면 이름 옆에 「변경됨 · 저장 필요」가 붙고, 저장하면 「저장됨」으로 바뀝니다.
- 저장하지 않은 변경이 있는 상태에서 다른 스케줄을 불러오면 먼저 확인을 받습니다.
- 작업본과 저장 목록은 브라우저 `localStorage`에 남습니다 (`tcr-db-engine-schedule-v1`, `tcr-db-engine-library-v1`). 서버나 로그인이 없으므로 다른 사람과 공유하거나 브라우저 데이터를 지울 예정이라면 JSON으로 내보내 두세요.

## 실행

```bash
npm install
npm run dev
```

브라우저에서 [http://127.0.0.1:43147](http://127.0.0.1:43147) 을 엽니다.

개발 서버는 `127.0.0.1`과 `localhost`에서 오는 요청을 허용합니다 (`next.config.ts`의 `allowedDevOrigins`). 다른 호스트로 띄우면 클릭이 동작하지 않을 수 있습니다.

프로덕션 빌드:

```bash
npm run build
npm start
```
